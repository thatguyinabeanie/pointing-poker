# History Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a per-room session history (Queue | History tabs in the left pane) and a Jira ticket
changelog (third ticket tab), as the spec describes.

**Architecture:** Session history is pure state in `server/game.ts`, written on reveal and on a
successful save, and sent to every viewer in the snapshot. Ticket history is read by
`server/jira.ts` from the changelog endpoint in parallel with comments and sent on `Ticket`. The
client adds two list components and a left-pane tab wrapper; the queue row shell is extracted so
both lists share it.

**Tech Stack:** Node 26 (type stripping), Fastify 5, React + MUI, Vite, Biome.

**Spec:** `docs/superpowers/specs/2026-10-20-history-design.md` (binding).

## Global Constraints

- No tests and no test script (repo CLAUDE.md). "Test" in this plan means the gate plus the final
  browser check.
- Gate: `npm run format && npm run lint && npm run tsc:check && npm run build`, exit status checked
  unpiped. Parallel implementers run only `npx biome check --write <own paths>` and
  `npm run tsc:check`, and ignore tsc errors that sit only in another task's files.
- Server: erasable syntax only, explicit `.ts` relative imports, `env()` only inside functions.
- Failures are discriminated results, not exceptions. Comments explain why.
- Never log ticket content or the Jira token. Changelog logs carry counts only.
- No new client commands. No storage on the server. Session history is lost on restart.
- Session history cap: **50** rows. Ticket history cap: **newest 100** entries.
- `edited: true` for the Description and Environment fields and any value over **200** characters.
- Changelog values are rendered as text, never as HTML.
- Copy fixed by the spec: "Nothing pointed yet in this room.", "No history",
  "Showing the latest 100 changes", "consensus", "re-voted", "✓ saved", "–" for an empty side.
- Never click "Save to Jira" in dev: the dev server talks to the real Jira.

## Review Focus

1. A save that finishes after the room moved to another ticket or round must still mark that
   key's history row saved and broadcast (today the stale-round branch does not broadcast). Owned
   by Task 2.
2. A reveal where every vote is "?" or "☕" (average null): the row still records, with no avg or
   range text; the client must not render "avg null". Owned by Tasks 2 and 5.
3. A changelog with more than 100 entries, or a Jira page size smaller than 100: newest 100,
   newest first, `historyTruncated` true; a failed later page degrades to empty history, never a
   failed ticket load. Owned by Task 3.
4. Changelog items with null `fromString`/`toString`, unknown fields, or HTML-looking text: shown
   as plain text with "–" for null, never injected as HTML. Owned by Tasks 3 and 4.
5. Clicking the Jira key link in a history row opens Jira without loading the ticket; the row of
   the loaded ticket is highlighted and not clickable, exactly like the queue. Owned by Task 5.

### Task 2: Session history on the server

Model: sonnet. Runs in parallel with Tasks 3, 4, 5.

**Files:**
- Modify: `server/game.ts`
- Modify: `server/ws.ts`

**Interfaces:**
- Consumes: `GameState.history`, `SessionHistoryEntry` (Task 1); `summarize` (existing).
- Produces: `recordReveal(state: GameState, now: string): GameState`,
  `markHistorySaved(state: GameState, key: string, points: number): GameState`,
  `reveal(state: GameState, now: string = new Date().toISOString()): Result`. All exported from
  `game.ts`.

- [ ] **Step 1:** `recordReveal`: no ticket → same state. Otherwise build the row (key, summary, issueType, url from the ticket) from
  `summarize(state.players.values())` (`voters` = players with a non-null vote), remove any row
  with the same key, set `revoted` to whether one existed, carry over its `savedPoints` (else
  null), put the new row first, and slice to `MAX_HISTORY = 50`.
- [ ] **Step 2:** `reveal` applies `recordReveal(next, now)` after the phase change. The default
  `now` keeps the function deterministic for callers that pass a time and avoids touching the
  `ws.ts` call site.
- [ ] **Step 3:** `markHistorySaved`: map the row with that key to `savedPoints: points`; return
  the same state object when no row matches (so callers can skip a broadcast).
- [ ] **Step 4:** `ws.ts` save callback: when `res.ok`, apply `markHistorySaved(state, key,
  points)` in both the current-round and stale-round branches, and broadcast in the stale-round
  branch when the state changed (Review Focus 1). Keep the existing `markSave` behavior.
- [ ] **Step 5:** `npx biome check --write server/game.ts server/ws.ts`; `npm run tsc:check`
  clean for these files. Commit only these paths.

### Task 3: Ticket changelog in the Jira client

Model: sonnet. Runs in parallel with Tasks 2, 4, 5.

**Files:**
- Modify: `server/jira.ts`

**Interfaces:**
- Consumes: `TicketHistoryEntry`, `TicketHistoryChange` (Task 1).
- Produces: `Ticket.history` (newest first, at most 100) and `Ticket.historyTruncated` from
  `getIssue`. Internal: `fetchHistory(key: string): Promise<{ history: TicketHistoryEntry[];
  truncated: boolean }>`.

- [ ] **Step 1:** Constants `MAX_HISTORY_ENTRIES = 100`, `MAX_HISTORY_VALUE_CHARS = 200`,
  `EDITED_FIELDS` = description and environment (compare lowercased `field`/`fieldId`).
- [ ] **Step 2:** `fetchHistory`: `GET /rest/api/3/issue/{key}/changelog?startAt=0&maxResults=100`.
  Read `total`, `values`. If all entries fit, use them. Otherwise start at
  `max(0, total - 100)` and page forward (Jira may return fewer than 100 per page) until 100
  entries or `isLast`/an empty page, bounded to 10 requests. `truncated` = start > 0. Any failed or
  unreadable page → `{ history: [], truncated: false }` plus a `logger.debug` with key and reason,
  matching `fetchComments`.
- [ ] **Step 3:** Map each raw entry to `TicketHistoryEntry`: `id` (string, index fallback),
  `author` = `author.displayName` or "Unknown", `createdAt` = `created` or "", `changes` from
  `items` (`field` as given, `from`/`to` = `fromString`/`toString` or null; when edited, both null
  and `edited: true`). Drop entries with no changes. Reverse to newest first.
- [ ] **Step 4:** In `getIssue`, run `fetchComments` and `fetchHistory` with `Promise.all`; add
  `historyCount` and `historyTruncated` to the existing "jira issue rendered" debug log.
- [ ] **Step 5:** `npx biome check --write server/jira.ts`; `npm run tsc:check` clean for this
  file. Commit only this path.
